## Where each lock lives (`catalog-mcp/live/lib/door.mjs`)
- Lock one, line 189: `if (!authorized(request)) return json(401, { error: "unauthorized" });` It is the first line of the request handler, before the body is even read. The token is compared as SHA-256 digests with `timingSafeEqual`.
- Lock two, where the scope is decided: line 53, `const ACCOUNT = process.env.DOOR_ACCOUNT_ID`, a server setting the caller never sees. It is applied at lines 91–92 (`set local role app_rw` and `app.user_id` = ACCOUNT, so row-level security applies) and at line 129 (`where owner_id = $1` bound to ACCOUNT). The explicit owner filter is needed because RLS alone lets anyone read other users' tradeable copies, and Bob's Elly De La Cruz is tradeable.
- The tool takes only `query`, `year`, `sport` and `limit`. Any other input is rejected (knock 3b).

## Refusal note
Knock 2 was refused with 401 because the door checks for the issued token before it does anything else, and the refusal body names nothing about the service. Knock 3 came back empty because the search is scoped to the account the token maps to, set on the server, and no caller input can reach outside it. Knock 4 found nothing to call, because delete was never built.
